# Tiny World: notes for Claude

A tiny procedural planet with live weather, built in Three.js. Uri develops it from his phone, so Claude does the editing, committing and pushing.

- The whole app is `index.html` (Three.js 0.187 and three-mesh-bvh 0.9.17 via an import map from jsDelivr, plain DOM UI). No build step.
- Pushing to `main` deploys to GitHub Pages: https://senzaiken.github.io/tiny-world/
- **Build stamping:** install the hook once per clone: `cp tools/pre-commit .git/hooks/pre-commit && chmod +x .git/hooks/pre-commit`. It writes a new `BUILD` id into `index.html` and `version.json` on every commit touching the app, so open copies show the "new version" banner. Don't edit `BUILD` by hand.
- **Keep the wiki current.** Every change to a system or number updates the matching page in `docs/` and adds an entry to `docs/changelog.md` in the same commit.
- Don't break saves (`localStorage` key `tinyworld-save-v1`; the JSON carries `v`). Format v2 stores the sculpted difference from the generated terrain (Int16 ×50000, gzipped). `migrate()` resamples v1 saves (absolute heights at detail 63/127) by barycentric interpolation over the old lattice; reuse it if `S` changes again. Note format changes in the changelog.
- The terrain is chunked (see `docs/world.md`). Change heights, then call `applyChange(list,count)` so normals, colours, uploads and raycast trees stay in step; `refreshAll()` rebuilds everything.
- Weather is local-only for now: buttons drive presets in `PRESETS`. The plan is to feed real WeatherKit data through a small server-side proxy (the JWT signing key must never ship in the page).
- Before pushing: run a headless render (Chromium + `npm i three@0.187.0`, routing the jsDelivr URLs to `node_modules` (`npm i three@0.187.0 three-mesh-bvh@0.9.17`) since the CDN is blocked in the sandbox). `window.__tw` exposes test hooks: `setWeather`, `heights`, `sculptAt`, `undo`, `ff(seconds)` (fast-forwards weather, since software-rendered frames are slow), `view(dist, angle|null)`, `faceHeight(h)` (turns a vertex near height h toward the camera), `flick(x,y,z)` (sets the spin velocity), `globeQ()`, `fling`, `drawn`, `detailed`, `jobs` (pending fine builds), `lod()`, `stats()`, `buildTime()`, `sea`, `lakes`, `faceLake()`, `spinOff` (set true to stop the auto-spin while testing), `sail` (ship state), `launchAt(x,y,z)`, `leaveSail()`, `waterDir(sunny)` (a deep ocean direction, optionally the sunniest), `seaOffset(x,y,z)`. Sailing is documented in `docs/sailing.md`; keep `seaOffset`/`windAtJS` in step with the water shader. Wait for `#loader` to disappear before testing; boot is async.
